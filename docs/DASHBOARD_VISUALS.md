# Изображения кабинета Dropvia

По запросу владельца HTML-файловая панель на лендинге заменена сгенерированными растровыми изображениями. Использован встроенный `image_gen` через skill `imagegen`; CLI/API fallback, ключи и новые npm-зависимости не использовались.

## Ресурсы и происхождение

`public/images/dashboard/` содержит восемь экранов: desktop/mobile × light/dark × en/ru. Каждый экспортирован в два размера WebP: desktop800/1600px, mobile480/960px. Всего16файлов, около788KB суммарно. Одна страница загружает выбранные по теме/языку/viewport варианты, а не весь набор. На mobile оба picture выбирают мобильный экран; одинаковые выбранные URL используют общий browser cache.

Полные финальные prompts, способ генерации, размеры и bytes находятся в `docs/dashboard-image-manifest.json`. Сначала создан desktop dark EN, затем уточнены монохромные иконки; остальные варианты получены через built-in edits с сохранением композиции и локализацией. Все финальные результаты просмотрены. В проект сохранены оптимизированные изображения; оригиналы генератора остаются в его штатной папке.

`scripts/export-dashboard-images.mjs` выполняет только resize/encoding PNG→WebP через установленный Chromium, без перерисовки интерфейса и без Python/Pillow. Для повторного экспорта нужен локальный `artifacts/dashboard-inputs.json` с key/path/prompt для файлов генерации. Путь к конкретной машине не включён в публикуемые ресурсы. Не заменять эти изображения HTML/CSS-имитацией: требование владельца — именно generated bitmap.

## Дизайн

Информационная организация сверена с [официальным описанием веб-интерфейса Dropbox](https://help.dropbox.com/installs/homepage): навигация, поиск, файлы/папки. Визуальная система Dropvia: midnight/ice, тонкие линии, inset поверхности,16px panels, pill controls, violet только для Upload внутри иллюстрации. Не использованы логотипы Dropbox, Adobe, чужие планы/лимиты или отзывы.

Mobile — responsive web page с меню, поиском, строкой вкладок и списком файлов. По последующему запросу владельца изображения оформлены отдельными презентационными рамками: окно Safari на macOS и iPhone с Safari, адресом dropvia.fun, status bar и home indicator. Это браузерное веб-приложение; нижние иконки принадлежат Safari. Сгенерированные экраны кабинета сохранены без изменений.

`browser-frames.tsx` содержит только внешнее оформление устройств. Панели браузера декоративны, скрыты от accessibility tree и не создают ложных интерактивных controls. Desktop/tablet используют сетку с общей нижней линией; iPhone перекрывает правый край desktop-окна на15% своей ширины. Перекрытие задаётся общей колонкой grid, независимо от transform анимации. На узком viewport показан один iPhone. Соотношение сторон телефона390:844 фиксировано, экран ограничен внутренними границами корпуса.

Подписи интерфейса локализованы в самих изображениях. Названия файлов, даты, размеры и инициалы в иллюстрации — демонстрационные данные изображения, не реальные записи аккаунта. Публичной метки concept/demo не добавлено. Новые backend/account features не создавались.

## Загрузка, motion и доступность

`FileScene` использует picture media/srcset для темы, размера и языка. Размеры и aspect-ratio зарезервированы; главный visual eager/high priority. У обоих экранов локализованы alt с указанием устройства и Safari. На mobile скрыто всё desktop-окно. Картинки не интерактивны и не добавляют tab stops.

Framer Motion запускает appearance всей рамки после фактической загрузки: opacity0→1, смещение12→0px,900ms с мягким ease-out; второй visual с100ms offset. Масштабирование отсутствует. Для уже закэшированного image.complete запуск происходит при mount. Listeners и animations очищаются при unmount. Без JS изображения видимы в SSR HTML. Reduced motion исключает движение через hook и CSS; no-JS не зависит от анимации для отображения.
